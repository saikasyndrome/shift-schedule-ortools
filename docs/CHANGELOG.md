## [0.2.0] — 2026-10-27

### 문제와 해결

#### 1. 휴일 예외를 넣으면 3·4연휴가 생김

| | |
|---|---|
| **문제** | `exceptions`로 `休み`/`有給`을 지정한 구간은 “의도된 연휴”로 보고 `max_consecutive_off`를 **건너뛰고** 있었음. 예외 옆날에 자동 `休み`가 붙으면 상한(예: 2일)을 넘는 연휴가 정상 결과처럼 나옴. |
| **해결** | 예외 지정 여부와 관계없이 **연속 휴일 상한을 절대 적용**. 예외만으로 이미 상한을 넘으면 솔버 전에 명확한 hard_error, 아니면 INFEASIBLE. |
| **설정 영향** | sample의 Alice 25–27일 3연휴 예외 → 상한 2에 맞게 27일 예외 제거. |

#### 2. “明け는 근무”인데 6연근처럼 보임

| | |
|---|---|
| **문제** | 근무일수(`出勤` / `is_work_shift`)는 `明け`를 **근무**로 세는데, `max_consecutive`만 `明け`를 비근무로 빼 두어 판정이 어긋남. 예: `早×4 + 夜勤 + 明け` = 표상 6일 연속인데 알고리즘은 5일로 통과. |
| **해결** | `max_consecutive`에서도 **`明け`를 근무로 포함**. `休み`/`有給`만 연속을 끊음. 휴리스틱(`consecutive_count`)·테스트도 동일. |

#### 3. 판정 기준 정리 (현재 동작)

| 코드 | 근무일수(`出勤`) | `max_consecutive` | `max_consecutive_off` / `off_days` |
|------|------------------|-------------------|-------------------------------------|
| 早/遅/日勤/夜勤 | 근무 | 근무 | — |
| 明け | 근무 | 근무 | 미포함 |
| 有給 | 근무 | 비근무(연속 끊김) | 연속휴일 쪽·`off_days` 미포함 |
| 休み | 휴무 | 비근무 | 휴무 |

### 이미 있는 진단 (부분 대응)

INFEASIBLE 시 `_diagnose_infeasibility`가 제약 그룹을 **하나씩 완화(relax)** 해 보며, “이 규칙을 풀면 풀린다”는 힌트를 출력합니다.

대상 그룹 예: `night_required` / `off_days_exact` / `required_coverage` / `max_consecutive` / `max_consecutive_off` / `ojt_solo` / `max_nights` / `ojt_count`.

### 알려진 한계 · 개선점 (다음)

CP-SAT는 **전역 가능해/불가능**만 강하게 증명합니다. 그래서 실무에서는:

1. **결과 중심 수정이 되기 쉬움**  
   Excel/표를 보고 “여기가 이상하다” → YAML을 고치고 다시 돌리는 루프. “어느 규칙·어느 예외·어느 날짜가 핵심 충돌인지”가 한눈에 안 나옴.
2. **에러 메시지가 원인 한 줄로 안 떨어지는 경우**  
   단일 그룹 relax로도 안 풀리면 “여러 규칙이 동시에 충돌” 수준만 나오고, **exceptions ↔ rules**, **사람·날짜 단위**까지는 아직 안 짚어 줌.
3. **개선으로 넣을 것 (로드맵)**  
   - **분할 실행 진단 강화**: 지금 1개씩 완화에 더해, 2개 이상 조합 / 이분(binary) 완화 / “예외만 끈 모델” 등으로 **최소 충돌 집합**에 가깝게 좁히기.  
   - 충돌 시 **사람·날짜·규칙 키**가 들어간 메시지를 hard_error에 직접 노출.  
   - CLI에서 `--diagnose`만 돌리거나, 성공해도 “아슬아슬한 제약” 리포트를 선택 출력.  
   - (가능하면) 예외 강제와 절대 규칙이 정면충돌할 때 “이 예외를 빼면 / 이 rule을 올리면” 후보를 제시.

→ 알고리즘이 전역 최적화인 한, **원인 특정은 진단 기능을 키우는 쪽**으로 가는 수밖에 없고, 그 축을 다음 버전의 주 개선으로 둔다.
